# Relating Documentation Finalization Pack

Relating is the CRM-oriented relationship lifecycle component. The code name is `Relating`; the root business object is `Relationship`; the market label is `CRM`.

This pack consolidates the hard rules, source-vacuum decisions, object matrix, boundary rules, and implementation roadmap into one entry point for future agents and contributors.

## Canon

- Component: `App`.
- Root object: `Relationship`.
- Market category: CRM (`Customer Relationship Management`).
- Route prefix: `/relating`.
- Owner scope: relationship lifecycle, lead lifecycle, opportunity lifecycle, business activity, timeline projection, campaign attribution, case triage, AI suggestions, business decision trace.
- Non-owner scope: CRUD, vendor master data, product master data, order ownership, payment ownership, shipment ownership, access rules, project ownership, message storage, document/media ownership.

## Non-negotiable rules

1. Relating never creates CRUD controllers.
2. Relating never declares CRUD YAML routes.
3. Relating never creates CRUD operation routes.
4. Relating never introduces `index`, `create`, `read`, `update`, `delete`, `list`, `show`, `edit`, `store`, `patch`, or `remove` as public route/action surfaces.
5. Relating exposes business routes only.
6. Relating does not own neighbor entities.
7. Relating stores scalar references and normalized signals from neighbors.
8. Relating uses EntityFirst design; migrations are generated by the host app when the host is ready.
9. Relating does not use SQL-first design. Special read-model performance queries must be separate, reviewed, and documented.
10. Relating never lets Doctrine entities leak into API/ViewObject payloads.
11. Relating AI is suggestion-first: raise, review, apply/reject, trace.
12. Relating policy/trace/audit are business-decision surfaces, not CRUD audit tables.

## Source-vacuum meaning

Open-source CRM projects are used as reference catalogs, not code sources. Legacy design is transformed into Symfony-oriented `App` language.

- Twenty contributes modern object/view/workflow/agent thinking.
- EspoCRM contributes metadata/entity/layout manager thinking.
- SuiteCRM contributes a broad module catalog and long-tail CRM coverage.
- OroCRM contributes customer 360, lead/opportunity sales lifecycle, forecast/dashboard references.
- Krayin contributes compact SMB CRM forms, pipeline, activities, custom attributes, and quotes/product-interest references.
- CiviCRM contributes relationship graph, community/nonprofit cases, activities, contributions, memberships, events, and dedupe/merge surfaces.
