# Doctrine mapping readiness

Relating is EntityFirst. The skeleton declares Doctrine attributes on entities, but it does not ship migrations.

## Rules

- Entity classes describe intended persistence shape.
- Migrations are generated only inside the host application.
- No SQL-first schema files are introduced.
- No direct SQL query layer is introduced for core lifecycle behavior.
- Read-model/reporting SQL is allowed only as a later explicit performance exception.

## Index shape

S1 adds tenant-aware indexes to high-volume entities:

- `relating_relationship`
- `relating_lead`
- `relating_opportunity`
- `relating_activity`
- `relating_timeline_event`
- `relating_relationship_signal`
- `relating_case_record`

## Review checklist before migration diff

1. Confirm table prefix matches host conventions.
2. Confirm reference column length with neighboring components.
3. Confirm JSON columns are acceptable for metadata/context fields.
4. Confirm bigint amount fields map correctly to the target database.
5. Confirm no CRUD route/controller is generated by the Relating component.
